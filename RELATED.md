# Related work

Chonks was built independently. Recent literature has converged on the same core design: deterministic AST-derived graphs rather than LLM-extracted ones, typed structural edges alongside embeddings, and anchor-first graph exploration.

- **GraphRAG (original):** [From Local to Global: A Graph RAG Approach to Query-Focused Summarization](https://arxiv.org/abs/2404.16130), Edge et al., 2024. The paper that named the pattern: retrieval over an entity graph and community summaries instead of flat chunks. Chonks applies the idea to code, where the graph needs no LLM extraction because the structure is already in the AST.
- **AST vs LLM-extracted graphs:** [Reliable Graph-RAG for Codebases: AST-Derived Graphs vs LLM-Extracted Knowledge Graphs](https://arxiv.org/abs/2601.08773), 2026. A head-to-head of the two graph-construction strategies on the Shopizer corpus: LLM extraction skipped 377 files, and on correctness "DKB achieves the highest correctness, LLM-KB is close behind" — a modest edge for the deterministic graph, not a wide margin. The paper's clearer gap, 43/45 against 31/45, compares the AST-derived graph against flat-vector RAG, a different comparison than AST-vs-LLM-extraction. Still the closest published support for Chonks' bet on deterministic extraction, though narrower than a first read suggests.
- **Tree-sitter graphs over MCP:** [Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP](https://arxiv.org/abs/2603.27277), 2026. The closest published system: a persistent tree-sitter graph, MCP tools, and call-graph traversal. Their headline result is 83% answer quality against 92% for a file-exploration agent, at a tenth of the tokens and 2.1 times fewer tool calls.
- **Graft:** [trailhq/Graft](https://github.com/trailhq/Graft), NanoNets, MIT license. The closest shipped rival: lexical retrieval plus personalized PageRank, no embeddings, LLM-written summaries at build time, and hook/SKILL-based agent steering. They report a 12-point SWE-bench solve-rate gain at n=50 and ship telemetry. Chonks differs on embeddings, no LLM calls at index time, C++ support, and no telemetry; a direct ablation against Graft is a natural next comparison.
- **Confidence-gated graph expansion:** [LARGER: Lexically Anchored Repository Graph Exploration and Retrieval](https://arxiv.org/abs/2605.16352), 2026. Lexical matches become graph anchors, then confidence-filtered local expansion. The inspiration for research's `graph_seed_min_rel_score` gate.
- **Query reformulation for bug localization:** [Reformulate, Retrieve, Localize: Agents for Repository-Level Bug Localization](https://arxiv.org/abs/2512.07022), 2026. An LLM extracts identifiers, paths, and stack-trace terms from symptom-style bug report text before retrieval. `query_reformulate.py`'s rule-based extraction is the same idea without the LLM call.
- **Task-level context recovery:** [From Fragments to Paths: Task-Level Context Recovery for Large Industrial Codebases](https://arxiv.org/abs/2606.22906), 2026. Anchor-first, budget-constrained traversal of multi-relational repository structure at industrial scale, the same shape as `codebase_research` plus `trace_path`. Evaluated on 27 medium and 40 large SWE-bench-Verified tasks with gains of 1.6 to 9.2 points; the industrial-scale tasks are proprietary and not independently reproducible. Their Full Recall Rate is the same set-coverage measure as the feature-mapping eval in this repository — evidence that coverage pays off in task outcomes, a link that Q&A-style agentic evals, including this repository's, are too blunt to detect on their own.
- **AST-based chunking (peer-reviewed):** [cAST: Enhancing Code Retrieval-Augmented Generation with Structural Chunking via Abstract Syntax Tree](https://aclanthology.org/2025.findings-emnlp.430/), Findings of EMNLP 2025. Recursive AST-node splitting with sibling merging under size limits, the same core algorithm as Chonks' chunker (+4.3 R@5 on RepoEval over line-based chunking). Chonks adds completeness backstops (module residue, gap fill), macro self-healing, and a decoupled symbol index.
- **The counterpoint:** [Practical Code RAG at Scale: Task-Aware Retrieval Design Choices under Compute Budgets](https://arxiv.org/abs/2510.20609), 2025. In completion-style benchmarks, line-based chunking matches syntax-aware splitting and BM25 beats dense embeddings for code-to-code queries. The caveat is that their chunks are only embedding units. Chonks' chunks also carry names and typed edges for the symbol and reference graph, which line-based chunks cannot. Their per-task retrieval-mode finding independently supports the FTS and hybrid modes and the `scope` knob.
- **Code graph databases (NAACL 2025):** [CodexGraph: Bridging Large Language Models and Code Repositories via Code Graph Databases](https://arxiv.org/abs/2408.03910). An LLM agent over a code graph in a graph database. Chonks keeps the graph in SQLite tables instead, trading query expressiveness for a single file with no dependencies.
- **Survey:** [Retrieval-Augmented Code Generation: A Survey with Focus on Repository-Level Approaches](https://arxiv.org/abs/2510.04905), 2025. A map of the repo-level RAG space: retrieval strategies, graph and non-graph paradigms, agent architectures.
- **Loc-Bench:** [LocAgent: Graph-Guided LLM Agents for Code Localization](https://arxiv.org/abs/2503.09089), Chen et al., 2025. A graph-guided agentic localizer, released with the Loc-Bench benchmark. Chonks uses Loc-Bench's instances as the held-out localization set behind the README's n=100 numbers.
- **ripwire:** [redhat-et/ripwire](https://github.com/redhat-et/ripwire), Red Hat, Apache-2.0, C++23, no embeddings. Publishes its own Loc-Bench run (`bench/locbench/`), current as of its 2026-07-13 corrected evaluator: on a frozen 243-instance held-out split (of the same `czlll/Loc-Bench_V1` test set Chonks uses), its routed `--for` arm scores strict file@10 60.9%. Same Acc@k-strict definition as this repository's (all gold files within top-k, matched to the LocAgent paper), so the metric itself is comparable; the instance sets are not the same (their 243 vs. this repository's 100, both drawn from the 560-row test split), and their headline number is the output of a routing/acceptance layer on top of raw retrieval, not a flat ranked list the way this repository's Acc@10 is measured. Not yet a direct comparison. An identical-instance head-to-head against ripwire is a natural next measurement.
